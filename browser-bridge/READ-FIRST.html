Link Launcher browser setup

This optional package lets Run open a link in its assigned Chrome or Edge profile, even when that profile is closed. The main app stays a website or installable web app.

What is in this ZIP?

ComponentWhat it does
Browser extension
manifest.json, JavaScript and icon files		Connects the Link Launcher page to the local helper. It has access only to the app addresses listed in its manifest, plus native messaging permission. It is installed using Load unpacked; it is not a Web Store listing.
Windows helper
native-helper/native-host.cjs		Reads Chrome/Edge profile names and emails from local browser metadata, saves your chosen account-to-browser assignments and launches the selected profile for a clicked HTTP/HTTPS link. It runs on demand, with no background service.
Setup launcher
Setup.cmd		A readable Windows command file that runs the included PowerShell installer. It does not run merely by downloading or extracting it.
Installer and runtime
Install-Helper.ps1, Runtime.ps1		Uses installed Node.js 22+ or downloads an official Node.js 24 LTS Windows ZIP from nodejs.org and verifies its SHA-256 checksum. Copies the interpreter and licence into your local helper folder. Registers the helper for this Windows user in Chrome and Edge; no administrator access or system PATH change.

What data is used?

The helper receives your vault account email, selected account label and clicked website address. It reads browser profile names/emails and local profile locations for routing. It does not read passwords, cookies, browsing history or your link collection. Browser assignments stay in %LOCALAPPDATA%\DreamsLab\LinkLauncherHelper; names/emails join your encrypted cloud vault only when you explicitly add missing accounts in the app.

Install in four steps

  1. Extract this ZIP into a permanent folder. Read the included source files if you want to inspect what setup will run.
  2. Open chrome://extensions or edge://extensions. Enable Developer mode → Load unpacked → choose this extracted folder. If updating, replace files and click Reload.
  3. Double-click Setup.cmd. The command window shows progress or an error. Internet is needed if the runtime must be downloaded. If asked for the extension ID, copy it from the extension details.
  4. Reload the extension, refresh Link Launcher, open Browser profiles → Profiles, choose each account's actual browser profile and save.

Windows may show an unsigned-file or downloaded-file warning. This package is not code-signed. The setup command applies a PowerShell execution-policy override only to its own process; it does not change your permanent policy. Review the files and choose whether to run them. A checksum can confirm download integrity; it is not a malware certification.

Own cloud, mobile and incognito

For your own cloud, change the first matches entry in manifest.json to your actual HTTPS app origin plus /* and reload. Install the extension in each browser profile where you use Link Launcher; install the helper once per Windows user. Desktop helper switching supports Windows Chrome and Edge. Phone links use the current mobile browser. Incognito needs Allow in incognito and forgets browser-local choices when closed.

Remove or disable

  1. Disable or remove the extension from your browser's extension page.
  2. Run native-helper/Uninstall-Helper.ps1 to remove this Windows user's helper registration.
  3. To also remove the private runtime and saved browser assignments, delete %LOCALAPPDATA%\DreamsLab\LinkLauncherHelper.

Removing this package does not delete your cloud account or saved links. Website login is determined by the account already signed in inside the chosen browser profile.
